# Model RPS：开发计划

最后更新：2026-10-20。当前发布版本 v1.0.1。

本文保留后续方向、设计原则和未决问题。实际操作见 [README](../README.md) 与 [命令行与终端操作](cli.md)，现行规则见 [游戏规则](rules.md)，模块分层见 [架构](architecture.md)，配置说明见 [模板注释](../config.example.toml)。

## 设计原则

- 人类和模型都是同一种玩家，共用指令、裁判和信息权限；区别主要在输入方式。
- 保留 CLI，自由聊天与游戏行动分别推进。允许沉默，不要求模型每次收到聊天都回复。
- Red / Blue 是席位，模型或人类是参与者；相同模型也有独立历史和状态。
- 同一 BO 保留原始交流与自己的策略分析，新 BO 清空。接口思考仍属私有诊断。
- 前台只提供玩家有权看到的信息，调试窗口和私有日志不注入玩家上下文。
- 增量调整现有模块；传输、调度、裁判与终端各自负责自己的部分，依赖方向由架构测试固定。
- 显式控制命令才能换人，不把“不想玩了，换人”等任意聊天文本识别为操作。

## 当前开发：`codex/mcp-agent`

从 main 新建分支，复用原有裁判与调度，已完成：

- 独立 MCP 比赛：外部 Agent 对战模拟或配置中的 API 模型。
- 本机共享房间：两个人类终端、两个 MCP 桥接器或人类与 Agent 任意组合；令牌固定绑定 Red / Blue，支持 `/start`、`/stop`、`/status`、`/quit` 连续开场，每场独立状态与日志。
- `--shared-room` 固定 MCP 入口与 DSH 配置示例；同一 DSH 的两个对话可共用一个 MCP 进程，各自携带 `player_id`。
- 源码按 `core` / `llm` / `players` / `engine` / `ui` / `room` / `mcp_agent` 分层，依赖方向由测试强制，见 [架构](architecture.md)。

详细用法与验证范围见 [共享房间](shared-room.md) 与 [MCP 接入](mcp.md)。

### 下一步

- 真实宿主验证：两名真人手动终端试玩；DSH 两个真实模型对话的完整共享房间对局。
- 视结果决定是否扩展房间能力，再合并回 main 并发布。
- 清理遗留：旧 `local_secrets.py` 密钥文件兼容路径是否保留；`pyproject.toml` 中 ruff 目前忽略 F401（17 处历史未使用导入）。

暂不包含远程部署、共享房间局中接管或重连恢复。宿主控制自身会话生命周期；新 BO 使用新的 Agent 会话，避免继承前场记忆。
## 暂缓方向

- 上下文窗口管理：用户认为当前模型容量足够，暂不安排容量配置、预警、自动摘要或截断。继续保留本场完整历史及已有用量记录，出现实际容量问题时再评估。
- 局中任意更换模型、模型交还人类：当前只支持人类主动交给模型；进一步扩展前需另定输入与记忆继承规则。
- 聊天额度、自动行动期限与强制推进：现有观察中模型倾向尽早锁定；若持续互聊成为实际问题，再评估。单次网络超时仍属于技术失败，不自动判弃权。
- 图形界面、批量实验、自动统计与汇总报告：当前不优先。
- GPT 只返回标题式思考摘要：接受服务返回的实际内容，不补造、不继续专门追查。
