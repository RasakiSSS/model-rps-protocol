# 共享房间（实验）

适用版本：v1.1.0。

共享房间让两个人类终端、两个 MCP Agent，或人类与 Agent 的任意组合，通过本机的常驻服务进程对战。每次运行一场 BO，Red / Blue 各连接一个人类终端或 MCP 桥接器，双方到齐后才开赛。房间复用原有裁判与调度，不实现游戏规则；Agent 侧接入步骤见 [MCP 接入](mcp.md)。

服务只监听 `127.0.0.1`，不读取 `config.toml`、不请求模型 API，双人对战无需密钥或 MCP 依赖。

## 启动与入口

在第一个终端启动房间，然后在另外两个终端分别执行服务打印的 Red / Blue 连接命令：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m model_rps.room.server --bo 3
```

两个人类都使用[终端操作](cli.md#终端操作)中的共同指令。人类对 Agent 时，人类执行一方连接命令，只把另一方的 Agent 邀请发给 Agent；Agent 使用 `--shared-room` 固定 MCP 入口，由 `rps_start` 加入，无需反复修改配置。

| 入口 | 参数 |
| --- | --- |
| `model_rps.room.server` / `model-rps-room` | `--port` 默认 8765；`--bo` 默认 3；`--max-games`；`--initiative` 默认 simultaneous；`--move-policy` 默认 locked；`--red-analysis`、`--blue-analysis` 默认 optional；`--log-dir` 默认 logs |
| `model_rps.room.client` / `model-rps-join` | `--room-url` 房间地址；`--token` 本席位凭证，也可用环境变量 `RPS_SEAT_TOKEN`；`--name` 玩家名称 |
| `model_rps.mcp_agent.server --shared-room` | 推荐的固定 MCP 入口；`--agent-name` 默认 Agent，可由 `rps_start` 的 `name` 覆盖。房间地址及凭证通过加入工具传入，规则由房间决定 |
| `model_rps.mcp_agent.server --room-url 地址` | 兼容旧固定房间用法：`--token` 或 `RPS_SEAT_TOKEN`；`--agent-name` 名称；不能与 `--shared-room` 同用。只绑定最初加入的一场，连续开场请用 `--shared-room` |

各入口支持 `--help`。

## 管理指令

服务启动时自动开放第一场，之后在**服务端窗口**输入管理指令。这些指令不对玩家的 HTTP / MCP 接口开放；管道输入支持同样的指令，输入流关闭后服务仍运行，需 `/quit` 或 Ctrl+C 关闭。

| 指令 | 效果 |
| --- | --- |
| `/start` | 新开一场，沿用启动时的地址、token、BO 和规则；已有场次仍在等待、比赛或赛后聊天时拒绝覆盖，须先 `/stop` |
| `/stop` | 停止当前场（包括等待加入及赛后聊天），保留结果和日志，进入待机；不判弃权 |
| `/status` | 查看阶段、双方加入情况、已结算比分及日志位置 |
| `/quit` | 关闭服务并释放端口；Ctrl+C 同样关闭服务 |
| `/help` | 显示管理指令 |

## 房间生命周期

1. **等待**：服务打印 Red / Blue 的人类连接命令与 Agent 邀请。同一场每个席位只接受一个客户端，凭证绑定席位，客户端不能在请求里自行改身份。双方到齐才开赛，此前 `status=not_started`，不可提交行动。
2. **比赛与赛后聊天**：与普通对局相同。双方在赛后 EXIT 后状态为 `complete`，服务自动待机，结果保留到下一次 `/start`；旧场日志始终保留。
3. **换场**：每场拥有独立的 `room_id`、玩家连接、事件游标、行动令牌、提交记录、比分和日志目录，不继承上一场的比分、草稿或历史。旧心跳、断开、等待和提交都不能作用于新场。
4. **重新加入**：**同一服务端进程内地址与两方 token 不变**，只有关闭并重启服务端才生成新 token。人类重新执行原连接命令；Agent 用原 `room_url`、`token` 再次调用 `rps_start`，省略旧 `player_id`，保存新返回的 `state.player_id`。同场重复邀请幂等，保留 `player_id` 和客户端身份，包括加入响应丢失后的重试；无效邀请可修正后重试。

**连接与失联**：客户端每 10 秒发送心跳；主动断开或超过 90 秒失联会取消未完成比赛，不判弃权。思考或沉默期间只要连接仍在就不会失联。已在赛后 EXIT 的席位可先关闭连接，另一方继续聊天或退出。停止本场或关闭服务会取消等待输入并唤醒事件等待者。

**MCP 进程**：关闭共享 MCP 进程会断开它承载的所有玩家连接；只关闭一个宿主对话不一定断开该玩家，赛后应调用 EXIT。MCP 重启后旧 `player_id` 不可用，本版不恢复已占席连接，在服务端 `/stop` 后 `/start` 并用原邀请重新加入即可。更新项目代码后须重载宿主中的 RPS MCP 进程才会使用新协议，单纯新建对话不会更新运行中的 Python；连续开场本身不需要重载。MCP 可早于房间加载，房间只需在调用加入工具前启动。

**暂不支持**：共享房间的局中 `/handoff`、赛后 `/resume`、重连恢复、局中换人和远程部署。原有单终端 CLI 功能不受影响。

## 玩家接口

共享服务使用 JSON POST 的 `info`、`join`、`state`、`act`、`wait`、`ping`、`leave` 接口，随机连接凭证通过 `Authorization: Bearer` 绑定席位。`info` 只返回当前场次标识和阶段，不占席、不返回玩家视图。其余请求必须带匹配的 `room_id`，旧场请求整体拒绝，已进入旧场的长轮询仅返回旧场结果。正文上限 64 KiB，不开放浏览器跨域或分块请求。该 HTTP 接口承载项目自己的玩家协议；MCP 仍通过宿主启动的 stdio 桥接器提供工具，不是远程 HTTP MCP 服务。

MCP 工具与房间接口的对应关系：

- `rps_start`：幂等启动或加入。动态入口首次必须传 `room_url` 和 `token`，可选 `name` 只决定显示名；返回的 `state.player_id` 是本玩家本场的随机访问标识，之后刷新只传此标识。
- `rps_state`、`rps_act`、`rps_wait`：读取状态、提交共同指令、等待事件，都必须显式传入自己的 `player_id`。同一 MCP 进程可同时承载多个对话；缺失或未知标识拒绝，不回退到其他玩家，也不提供连接枚举，错误反馈只读取当前标识对应的视图。旧 `player_id` 不能改绑，也不会自动跟随新场。
- `revision` 随状态和公共事件变化，后三者通过 `after_revision` 返回后续公共事件；省略游标则从头返回。查看和等待不推进 Tick。人类客户端使用相同的游标和提交规则，并忽略晚到的旧视图、避免重复显示公共事件。
- `turn_token` 绑定玩家实例、当前局、阶段、输入请求、Tick 和行动权限；跨席位或过期令牌拒绝执行。每席位的每次新提交使用独立 `action_id`，重试相同载荷复用原 ID；同 ID 改载荷会拒绝，双方相同 ID 互不影响。同批指令先整体校验，错误时没有部分执行；`accepted` 仅表示交给调度器，最终执行或结算以公共事件为准。

MCP `--shared-room` 入口等待工具传入邀请，发现工具不会占席或创建比赛，共享入口只转发本席位指令与视图，不读取模型配置。独立 MCP 模式则自建比赛，对手使用模拟或模型适配器，见 [MCP 接入](mcp.md#独立比赛)。

## 信息边界与日志

人类和 Agent 只接收自己的 Player View、公共事件及赛后公开记录，接口不提供配置、密钥或对手私有日志。人类终端只在本地暂存行动草稿，聊天即时发送，`/endturn` 才提交完整行动，服务端仍统一校验。宿主可能拥有读文件等其他能力，本接口的信息边界不等同于操作系统防作弊隔离。

外部玩家等待输入不使用模型 API 超时。可独立提交 SAY；完整行动用 ENDTURN 结束，没有新 MOVE 则等待，已提交的拳型保留；分析要求沿用共同校验。整场结束后才公开双方有效分析，赛后可 SAY 或 EXIT。比赛结果中的 won / undecided 与连接阶段分开记录。

日志由比赛所在的服务进程统一保存，人类终端不另存私有日志。共享房间 `match_start` 的 `source` 为 `shared_room`，独立 MCP 模式为 `mcp`；游戏输入的 `request_start` / `request_end` 区分 `human` 和 `mcp`。本项目只保存 Agent 主动提交的分析，不能读取宿主内部思考、Token 用量或清空会话；新 BO 应新建宿主会话并加入新场。各场日志字段见 [日志与展示](logs-and-display.md)。
