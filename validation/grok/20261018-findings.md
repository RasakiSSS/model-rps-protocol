## 直接证据

基准流式原始响应的第 43 个事件正文片段是 `"},`，第 44 个事件直接变为 `type`。下一对象所需的 `{"` 没有出现在原始 SSE 中。其他动作边界重复出现相同缺字形态。

四次流式测试都用两条独立路径还原正文：一条直接从原始 SSE 提取并拼接 delta.content，另一条重放到项目的 sse_data 和 CompletionStream。结果逐字相同；程序没有遗漏已经收到的正文字符。

每组目录保存 `*-raw.txt` 原始响应（含私有思考，密钥已脱敏）、`*-content-deltas.json` 正文片段、`*-content.txt` 完整正文、`*-request.json` 不含鉴权的请求正文，以及 `*-summary.json` 结果。不要把原始响应误当作可执行指令。

## 结论与处理

本轮收到的流式数据本身已缺少 JSON 字符；不是缺结束标记、token 截断或本地拼接不一致。缺字发生在第三方服务或其上游，当前证据不能进一步归因，也没有验证官方直连。

当前 Grok profile 原本已设置 stream=false，此次保持不变。没有放宽游戏校验，也没有自动补符号。保持单独非流式可用；下文后续实验发现换行格式可以在已测样本中避开问题，尚未正式接入。

参数参考：[官方结构化输出](https://docs.x.ai/developers/model-capabilities/text/structured-outputs)、[官方流式接口](https://docs.x.ai/developers/model-capabilities/text/streaming)。官方支持流式结构化输出并不保证第三方实现与之等同。

成功样本均与目标逐字一致。紧凑多对象的三次失败内容完全相同：

```text
预期：{"items":[{"x":1},{"x":2},{"x":3}]}
实际：{"items":[{"x":1},x":2},x":3}]}
```

嵌套对象失败内容：

```text
预期：{"a":{"x":1},"b":{"x":2}}
实际：{"a":x":1},"b":x":2}}
```

缺失片段均为 `{"`。样本表明这与紧凑对象的表达形式有关，不限于数组或游戏动作；无法从客户端证据断定服务内部是过滤、分词还是其他处理出错。

最小测试目录：

三次均返回含 ANALYZE、MOVE、ENDTURN 的有效完整行动，其中一次另含 SAY；JSON 与游戏指令均通过现有校验。数据位于 `20261018_103932_191492`，每次请求及原始响应单独保存。
